Design

exproof.ai, on paper, in Computer Modern

Kept exactly from exproof.ai

  • The grid: label rail 8.5rem, text column 34rem (about 65 characters), margin-note column 15rem, gap 2.5rem; breakpoints at 1100, 860 and 560 pixels.
  • Root size 17px (18px above 1200px), sticky masthead with one half-strength rule, no rules between sections, cap-line alignment of labels with first lines, margin notes that open in place on phones.
  • Blood red as the only accent; green only for a found or converged state in animations.
  • The style guide and layout check, adapted rather than rewritten.

Changed

  • Ground. Paper white with ink text by default. The exproof.ai black palette becomes the Night mode, so the two sites are literally one design in two states.
  • Type. CMU Serif replaces ET Book for text and headings; CMU Sans Serif replaces IBM Plex Sans for labels and navigation; CMU Typewriter for code. All self-hosted, subset, under 200 KB.
  • Red on white. Blood red has a contrast ratio near 7:1 on white (2.9:1 on black), so links can show red at rest if you want. I recommend keeping exproof.ai behavior: ink at rest, red on hover.
  • Wordmark. "Aydin Mohseni" in CMU Serif with a red Δ, the simplex symbol, playing the role of ∃ on exproof.ai. A proposal; drop it if it feels like branding.

Chalk on paper, kept faint

Three devices, each easy to remove. A fixed paper grain at about 5% opacity (visible behind this page). Animation strokes in graphite with slight width variation and a grain mask, so lines read as drawn rather than rendered. Hand-drawn figures in the Sketchbook. Text, controls and tables stay crisp; texture never touches them.

Risk: Computer Modern was cut for print at 10pt, and its hairlines go thin on low-resolution screens, mostly Windows. Mitigation: the larger exproof.ai sizes help; test on Windows early; fall back to Latin Modern's 12pt optical size if body text looks weak.

Visuals

Three live models, in exproof.ai's animation style

Same vocabulary as the exproof.ai search tree: thin graphite lines, one moving light, smooth acceleration, a brief hold at events, dimming under the text column, a still frame under reduced motion.

1. Chaos on the simplex (background and hero)

Why this is the right headline: replicator dynamics on 2 or 3 strategies cannot be chaotic, because their state space is at most a triangle, a plane region, where the Poincaré–Bendixson theorem rules chaos out. Four strategies give a 3-dimensional simplex, the first place chaos can occur. So this is the minimal chaotic case, as you said. Sources: Skyrms, "Chaos in game dynamics," Journal of Logic, Language and Information 1 (1992); Arneodo, Coullet and Tresser (1980) on strange attractors in 3-species Lotka–Volterra systems, which Hofbauer (1981) showed equivalent to 4-strategy replicator dynamics; Sandholm, Population Games and Evolutionary Dynamics (2010).

On the page: the orbit drawn slowly across the background, as the search tree is on exproof.ai; in the hero, the same system with controls (start point, speed, rotation) and a "How it works" toggle.

2. Reflection (rational agency)

A Bayesian agent's credence about a coin. From the present, a fan of possible future credence paths in graphite spreads toward 0 and 1, while their average, in red, stays level at today's credence: van Fraassen's Reflection, P(A | Plater(A) = x) = x, shown as a martingale. A toggle swaps in an agent who expects to change its mind in a known direction; the average drifts, and the page notes the Dutch book that drift permits.

3. Refining a hypothesis space (AI safety and alignment)

A space partitioned into hypotheses plus a catch-all cell, shaded by posterior. As evidence arrives, mass moves; when the catch-all gains enough, it splits into new hypotheses and the partition refines. This is the evolving-algebra picture behind value learning with a catch-all, and links to Learning the Value of Value Learning.

Candidate fourth (metascience)

A community sharing evidence on a network converges or splits; with a toggle between agents seeing the same coin and agents seeing different data from it. Uses the lightweight model with Cole. Built after launch unless you want it on day one.

"Brian Gardner": I found no such source on 4×4 chaos. I read it as Brian Skyrms. Tell me if you meant someone else.

"Force simplex" I read as the simplex for four strategies. Its dimension is 3, which is why it draws as a tetrahedron.

Numerical check: with this payoff matrix, orbits started near the interior equilibrium (all strategies at ¼) stay interior, and the largest Lyapunov exponent is about 0.16 from three different starts. Orbits started far away go to the boundary, so the start point matters.

Stack

Static site, GitHub Pages, one repository

Recommendation: Eleventy, a small static-site generator, with content in YAML data files and pages in templates. It outputs plain HTML like exproof.ai, so nothing changes for visitors. It differs from exproof.ai in one place: exproof.ai repeats the header and footer in every file, which its own README flags as a chore. With 36 talks, 17 papers and 13 models, lists generated from data are cheaper to keep correct than hand-edited HTML.

  • Repository amohseni/aydinmohseni.com; GitHub Actions builds on every push and deploys to Pages.
  • A nightly rebuild, so talks move from Upcoming to Past on their date without anyone touching the repo.
  • Visualizations as plain JavaScript on canvas, one file each, no framework, following assets/search.js on exproof.ai.
  • The raw WordPress mirror kept in a separate private archive repository, never deployed.

Alternative: plain HTML, exactly like exproof.ai. Simpler toolchain, more hand edits. I would choose it only if you want to edit pages yourself in the GitHub web editor.

Cutover

Moving the domain without losing mail

The main risk is not the website. If InMotion runs your DNS and you cancel the account, everything on the domain stops resolving, including any mail and the /meet link on your email signature and in exproof.ai.

  1. Record every current DNS record and the registrar.
  2. Move DNS first. Copy every record into Cloudflare's free DNS (or the registrar's), mail records unchanged, and switch nameservers. The site is still served by InMotion at this point, so nothing visible changes.
  3. Mail. If a mailbox lives at InMotion, set up forwarding (for example Cloudflare Email Routing to Gmail) and confirm delivery before going further. If mail is hosted elsewhere, its records are simply copied.
  4. Verify the domain in your GitHub account (a TXT record), which prevents anyone else's Pages site from claiming it.
  5. Cut over. Lower the TTL to 5 minutes a day ahead; point the apex at GitHub Pages' four A records and four AAAA records, and www at amohseni.github.io; add the CNAME file; enforce HTTPS once the certificate is issued.
  6. Run in parallel two weeks with InMotion intact as rollback. Then transfer the domain out if InMotion is the registrar (unlock, auth code, check the renewal date), and cancel hosting.

Steps 2, 5 and 6 change live systems, so each waits for your go-ahead.

/meet: GitHub Pages cannot issue a true 302 redirect. A page with an instant meta refresh does the same job for people. If DNS is on Cloudflare, a redirect rule can give a true 302.
